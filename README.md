# YES ERP · Technician Time Management

A .NET 10 / ASP.NET Core Razor Pages module that books **technician time against jobs at Task level**,
auto-classifies Normal/Overtime, values it with industry/location labour rates, and feeds efficiency &
KPI reporting. It plugs into the existing YES ERP (Oracle) via the **Job Code**.

## Tech stack
- **.NET 10**, ASP.NET Core **Razor Pages**
- **Oracle** (Dapper + Oracle.ManagedDataAccess.Core)
- **Vertical Slice Architecture** — each feature is a self-contained folder under `Features/`
- **Serilog** (console + rolling file in `logs/`)
- **Bootstrap 5** + **Font Awesome**, responsive modern theme

## Solution layout
```
src/YesTm.Web/
  Common/Data        IDbConnectionFactory + Oracle implementation
  Common/Security    Roles (USER/ADMIN/SITEADMIN) + authorization policies
  Common/TimeCalc    TimeBookingCalculator (pure, unit-tested)
  Features/
    Authentication   Login/Logout, cookie auth, role resolution, demo sign-in (dev only)
    Dashboard        KPI home page
    TimeBooking      List + Entry transaction (Add-Task modal → grid)
    Administration   User Roles (site admin assigns who is a full admin)
    Shared           _Layout (top header + left nav), Error
db/
  01_tm_schema.sql   New TM_* tables, sequences, indexes
  02_seed.sql        Bootstrap site admin + sample masters/rates/tasks
tests/YesTm.Tests/   xUnit tests for the time calculation logic
```

## Getting started
1. **Create the schema** — run `db/01_tm_schema.sql` then `db/02_seed.sql` on your Oracle instance
   (as the application schema owner). `02_seed.sql` creates a bootstrap **siteadmin** login
   (`siteadmin` / `Admin@123`, USER_ID 9001 — change before production).
2. **Set the connection string** — edit `ConnectionStrings:Oracle` in
   `src/YesTm.Web/appsettings.json` (or use user-secrets / env var `ConnectionStrings__Oracle`):
   ```
   User Id=YES_TM;Password=****;Data Source=host:1521/SERVICE;
   ```
3. **Run**
   ```
   dotnet run --project src/YesTm.Web
   ```
   In the **Development** environment the login page also shows demo sign-in buttons
   (Site Admin / Admin / User) so the UI can be reviewed before Oracle is wired; screens fall
   back to demo lookups and clearly flag "database not reachable".

## Roles
| Role | Capability |
|------|-----------|
| USER | Enters & views their own time bookings |
| ADMIN | Enters all data and defines masters/parameters |
| SITEADMIN | Manages who is an ADMIN (User Roles screen); highest privilege |

Roles are stored in `TM_USER_ROLE` (extensible — history kept, highest active role wins).

## DB migration tool
`tools/DbMigrate` runs the `db/*.sql` scripts via ODP.NET (no sqlplus needed):
```
dotnet run --project tools/DbMigrate                 # runs 01_tm_schema.sql + 02_seed.sql
dotnet run --project tools/DbMigrate -- db/02_seed.sql
dotnet run --project tools/DbMigrate -- --query "SELECT * FROM TM_WORK_TYPE"
```
The seed is idempotent (NOT EXISTS guards) so it is safe to re-run.

## Phase roadmap
- **Phase 0 (done):** Foundation — VSA scaffold, Serilog, Bootstrap 5 theme (top header + left nav),
  cookie auth against `AMM_USER_DETAILS`, 3-tier roles + `TM_USER_ROLE`, Dashboard, Time Booking
  transaction with the Add-Task modal, calculation engine + unit tests, full `TM_*` schema & seed.
- **Phase 1 masters (done):** Job Location (table-driven, used by Time Booking + Job Card),
  Work Type, Industry, Customer→Industry, Labour Rate, Duty Timing, Task, Task Standard Hours —
  list + Add/Edit modal + activate/deactivate, secured to Admin+.
- **Job Card Entry (done):** admin-only CRUD over the ERP job table
  `MTL_TRANSACTION_JOB_OTHER_DTLS` (list/search, create, edit, dependency-guarded delete). Job
  codes are generated by the ERP's own numbering proc `PRO_GET_NEXT_DOCNO` (JCD) for consistency.
  Print is a future enhancement.
- **Phase 1 reports (next):** Efficiency & Productivity report, Performance Dashboard & Executive KPI.
- **Then:** monthly import utilities (Customer→Industry, Labour Rate, Task Std Hours); equipment-specific
  Task Std Hours lookup in posting; Finance posting (Job Code → FITD_TA_CODE1, Technician → FITD_TA_CODE2).
- **Phase 2:** Fixed-price & time-and-material billing.
